# 更新发布

v1.3.0 客户端仅使用 Gitee 获取更新，GitHub 镜像源码与发布产物。应用界面只显示版本、说明、进度和安装操作，不显示托管来源。

每次新打开应用或从后台返回时异步检查，没有每日次数限制；可以关闭自动检查，也可手动检查。后台 JobScheduler 仍每天尽力调度一次。运动期间暂缓检查，各入口共用并发锁，检查不上传运动数据、不带令牌、不自动下载或安装。

元数据是仓库根目录的 update.json，通过固定公开 raw 文件地址读取，无需 Contents REST API。schema 1 包含 applicationId、versionCode、versionName、notes、sha256、giteeUrl，保留 githubUrl 仅为兼容旧客户端；新版忽略它。

用户选择下载后，直接读取固定 HTTPS 发布附件地址，不查询 Release REST API，也不打开浏览器。重定向只允许 gitee.com / foruda.gitee.com。下载显示真实字节进度，支持取消、重开进度与失败重试。

文件先写私有缓存中的 update.part。验证响应长度、完整字节数、SHA-256、包名、版本、minSdk 和当前签名证书后，改名为 update.apk。取消或失败删除临时文件。进程结束后需要重新下载，不支持断点续传或签名密钥轮换。

通过只读私有 ContentProvider 将 APK URI 交给系统安装器。首次可能需要本应用的安装授权，最终安装由用户确认；不静默安装。下载和安装避开正在进行的运动记录。

发布顺序：同一签名构建与测试、隐私审查 → 推版本标签 → 上传 APK / 源码 ZIP / 校验文件 → 匿名下载验证 → 最后推主分支元数据。凭据及签名私钥放在仓库外。

v1.2.x 使用 REST API 和每日前台限额，v1.3.0 已替换该逻辑。旧版的联网行为只有覆盖升级后才会改变；若旧版检查失败，可直接下载安装发布包。

完整协议、实现文件、迁移清单及验证场景见 [Android 应用更新实现与复用指南](ANDROID-APP-UPDATES.md)。
